Pay via UPI — implementation plan

2026-10-21 · Spec: docs/superpowers/specs/2026-10-21-pay-via-upi-design.html

For agentic workers: REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps are checkboxes for tracking.

Goal: Each household member can store a UPI ID, and every settle-up suggestion whose payee has one gets a "Pay" action that shows a UPI QR code and an "Open UPI app" deep link with the payee and exact amount prefilled.

Architecture: One nullable column on household_members, carried through the existing member validator/actions/queries. A pure link builder in src/lib/upi.ts turns minor-unit amounts into the NPCI upi://pay string. A new client component UpiPayDialog renders that string as an SVG QR (qrcode.react) plus an anchor; SettleUpView opens it per suggestion row. Nothing writes to the DB from the dialog.

Tech stack: Next.js 16 / React 19, Drizzle + libSQL (migration via pnpm db:generate), Zod 4, Vitest, Playwright, qrcode.react (new), lucide QrCode icon.

Global constraints

  • Package manager is pnpm. Lint/format is Biome (pnpm lint); a PostToolUse hook auto-formats, so add an import in the same edit as its first use.
  • Money is stored as integer minor units; the UPI amount string is built from the integer, never from a float.
  • UPI IDs are stored trimmed and lowercased; regex ^[a-z0-9][a-z0-9._-]{0,254}@[a-z][a-z0-9]{1,63}$; error copy Enter a valid UPI ID, like name@bank.
  • Link shape, exact parameter order: upi://pay?pa=<vpa>&pn=<name>&am=<amount>&cu=INR&tn=<note>. pn and tn trimmed to 50 characters; values encoded with encodeURIComponent.
  • UPI UI renders only when useCurrency() === "INR". Opening the dialog, the link or the QR never writes.
  • e2e: never assert getByRole("alert"); auth via the passcode at /admin (e2e-pass); do not change seedE2EIsolationFixture.
  • Work on branch feat/pay-via-upi; conventional commit messages ending with the attribution line from the session.

Review focus

Inputs the spec implies but no feature test would otherwise exercise. Each has a test pinned in the owning task.

  1. Form posts without a upiId field (older callers, existing tests) → parses as absent, stores NULL, no error. → Task 1 validator test.
  2. UPI ID with surrounding spaces and capitals (" Name@OKAXIS ") → saved as name@okaxis. → Task 1 validator + action test.
  3. Non-positive or non-integer amount reaching the link builder → throws rather than emitting am=0.00 or am=12.5. → Task 2 test.
  4. Payee name or household name with &, =, # or Devanagari → encoded so the query string stays well-formed and the app shows the right name. → Task 2 test.
  5. Household name longer than 50 characters with multi-byte characters → note trimmed by code points, never splitting a character. → Task 2 test.

Task 2: The UPI deep-link builder

Files: Create src/lib/upi.ts, src/lib/upi.test.ts.

Interfaces — produces:

export function formatUpiAmount(amountMinor: number): string;     // 124000 → "1240.00"; throws on <= 0 or non-integer
export function buildUpiPayLink(input: {
  payeeVpa: string;      // already validated/lowercased
  payeeName: string;
  amountMinor: number;
  note: string;
}): string;              // "upi://pay?pa=…&pn=…&am=…&cu=INR&tn=…"
export const UPI_TEXT_LIMIT = 50;
  1. Write the failing tests src/lib/upi.test.ts: 
    describe("formatUpiAmount", () => {
  it.each([[124000, "1240.00"], [5, "0.05"], [100000000, "1000000.00"], [199, "1.99"]])("%i → %s", (m, s) =>
    expect(formatUpiAmount(m)).toBe(s));
  it.each([0, -100, 12.5, Number.NaN])("throws on %s", (m) => expect(() => formatUpiAmount(m)).toThrow());
});
describe("buildUpiPayLink", () => {
  it("builds the NPCI link with parameters in order", () => {
    expect(buildUpiPayLink({ payeeVpa: "priya@okaxis", payeeName: "Priya", amountMinor: 124000, note: "Outlay · Home" }))
      .toBe("upi://pay?pa=priya%40okaxis&pn=Priya&am=1240.00&cu=INR&tn=Outlay%20%C2%B7%20Home");
  });
  it("encodes reserved and non-ASCII characters in name and note", () => {
    const link = buildUpiPayLink({ payeeVpa: "a@b", payeeName: "R&D #1=ok", amountMinor: 100, note: "घर" });
    expect(link).toContain("pn=R%26D%20%231%3Dok");
    expect(link).toContain("tn=%E0%A4%98%E0%A4%B0");
    expect(link.split("&")).toHaveLength(5);
  });
  it("trims name and note to 50 code points without splitting a character", () => {
    const name = "अ".repeat(60);
    const link = buildUpiPayLink({ payeeVpa: "a@b", payeeName: name, amountMinor: 100, note: "x".repeat(80) });
    const pn = decodeURIComponent(new URL(link).searchParams.get("pn") ?? "");
    expect(Array.from(pn)).toHaveLength(50);
    expect(new URL(link).searchParams.get("tn")).toHaveLength(50);
  });
});
  2. Run to see them fail: pnpm vitest run src/lib/upi.test.ts → FAIL (module missing).
  3. Implement src/lib/upi.ts: formatUpiAmount checks Number.isInteger(m) && m > 0 (else throw new RangeError) and returns `${Math.floor(m / 100)}.${String(m % 100).padStart(2, "0")}`. A private clip(s) uses Array.from(s.trim()).slice(0, UPI_TEXT_LIMIT).join(""). buildUpiPayLink concatenates the five pairs in the fixed order with encodeURIComponent on each value (do not use URLSearchParams; it emits + for spaces).
  4. Run the tests: PASS. Note: new URL("upi://…").searchParams works in Node for a custom scheme; if it does not, parse with a regex in the test instead.
  5. Commit: feat(upi): pure upi://pay link builder.
