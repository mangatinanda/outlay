# Source Directory Context

## Component Guidelines
- All `components/ui/` files are auto-generated by shadcn/ui CLI. Do not edit manually.
- Feature components go in their own directory: `components/dashboard/`, `components/expenses/`, etc.
- Shared/reusable components go in `components/shared/`.
- Layout components (sidebar, header, mobile-nav) go in `components/layout/`.

## Server vs Client Components
- Pages (`page.tsx`) are Server Components by default - they fetch data directly
- Interactive components (forms, charts, dropdown menus) must be `"use client"`
- Pass data from Server Components to Client Components via props
- Never import `db` or run queries in client components

## Database Patterns
- `lib/db/schema.ts` - Single source of truth for all table definitions
- `lib/queries/` - Read-only functions used in Server Components
- `lib/actions/` - Server Actions for mutations (create, update, delete)
- `lib/validators/` - Zod schemas shared between client-side forms and server-side actions
- Always call `revalidatePath()` after mutations to refresh cached data

## Adding New Features
1. Define schema changes in `lib/db/schema.ts`
2. Create Zod validator in `lib/validators/`
3. Add query functions in `lib/queries/`
4. Add Server Actions in `lib/actions/`
5. Build UI components
6. Create page that composes everything

## Household Context
- Currently uses a single default household (first one in DB)
- `getDefaultHousehold()` from `lib/queries/household-queries.ts` returns it
- Multi-household support can be added by passing householdId through auth session
